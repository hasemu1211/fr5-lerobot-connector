## Why

Approved FR5 demonstrations must become learned behavior with fair evaluation and an affordable, reproducible path on the available workstation. Admission, a completed short training job, and low offline loss each establish different facts. None establishes physical effectiveness or generalization by itself.

## What Changes

- Keep one native admitted training path through the existing public wrapper and official LeRobot trainer. Bind the exact selected data, train-only normalization, checkpoint processors and held-out evaluation.
- Measure resource use and learning progress separately. Use cheap bounded pipeline probes to decide whether a sustained learning run is viable; compare learned checkpoints on fixed evaluation conditions.
- Analyze successful demonstration coverage and held-out errors alongside failures to identify useful data acquisition, while preserving Curator and Rollout ownership.
- Support exact-batch human decisions and explicit standing local-training delegation through the same admission owner. Preserve immutable original data, no train/evaluation leakage, one GPU owner and separate physical authority; delegation is not a fabricated human batch decision.

## Capabilities

### New Capabilities

- `learning-evaluation-loop`: approved-data learning, fair offline evidence and resource-informed next outcomes.

## Impact

Owned training/profile/receipt/checkpoint/evaluator modules, existing focused tests, public training/evaluation wrappers and training documentation. This draft does not issue approval, authorize a GPU run, change dependencies, own candidate selection, or introduce a rollout executor. Orca owns attempts, resource coordination and evidence references; this draft owns desired behavior and acceptance.
