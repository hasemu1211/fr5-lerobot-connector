# FR5 포트폴리오 — 구성과 표현의 재검토

2026-09-06. 첫 시안을 직접 렌더하고 사용한 뒤 받은 피드백으로 기준을 수정했다. 사용자가 지적한 문제는 글의 말투뿐 아니라 전체 구조의 부재, 한 화면에서 경쟁하는 주제, 아키텍처·기능·연구 성과를 한꺼번에 읽어야 하는 부담이었다. 이 문서는 표현의 판단 근거이며 실험 결과 장부가 아니다.

이후 사용자는 **전체 틀을 잡는 일과 현재 증거로 가치·비중을 정하는 일을 구분하라**고 교정했다. 최근 받은 Learning 결과를 대표 사례로 골라 상세 페이지까지 구성한 판단은 너무 빨랐다. 현재 결과는 전체 개요·시스템 구성·미정렬 세부 후보만 다룬다. 아래의 직무 관련성과 증거 평가 기준은 내용을 실제로 채울 때 적용하며, 지금 대표 성과나 우선순위를 정하는 근거로 사용하지 않는다. 상세 증거의 추적 경로는 표현 책임자의 내부 탐색 자료로 유지한다.

## 무엇을 보여줄 것인가

검토자가 FR5 전체를 이해하고, 관심 있는 기능이나 연구를 충분히 파고들며, 그 결과가 다른 부분에 쓰이는 관계까지 확인할 수 있어야 한다. **전체의 종합성과 각 페이지의 선명함을 함께 평가한다.** 페이지 수나 특정 매체는 고정하지 않는다.

모방학습의 평가 조건·실패 해석과 데이터 엔지니어링의 입력 검증·계보·운영 복구는 서로 다른 깊이가 필요하다. 이를 하나의 loss 수치로 대표하지 않는다. Physical Intelligence의 [Data Systems 역할](https://jobs.ashbyhq.com/physicalintelligence/1f6cf3eb-f70f-480b-9fff-befd56c7fd07)은 데이터 수집·검증·학습 소비와 운영상 정확성을 함께 다룬다. 여기서 FR5에 맞는 검토 질문을 얻되, 해당 채용 공고의 대규모 인프라 경험을 FR5의 성과로 가져오지는 않는다.

## 글과 시각 구조의 기준

국립국어원이 게재한 장경희의 [「바른 글쓰기」](https://www.korean.go.kr/nkview/nklife/1999_4/1999_0405.pdf)는 정확한 어휘와 간결한 문장, 문단의 소주제와 글 전체의 계층적 구성을 설명한다(인쇄면 74–76, 83–85쪽). 이를 **문단 하나의 목적과 전체 주제에 대한 기여를 각각 확인하는 기준**으로 적용한다. 이 자료가 ‘~이다’를 AI 문체로 규정하는 것은 아니다.

이번 시안에서 ‘~이다’가 불편했던 이유는 사용자 취향과 실제 문맥으로 판단한다. 단정형 종결의 반복, 구체적인 행위 없이 등장하는 ‘신뢰성·역량·경계’, 선언문 같은 제목, 과도한 대비와 수사적 질문이 겹쳤다. 어미만 ‘~입니다’로 바꾸는 교정으로 끝내지 않는다. 누가 무엇을 바꾸었고 무엇을 확인했는지 먼저 쓴다. 제목은 주제나 관찰을 짧게, 본문은 자연스러운 설명체로 쓴다.

AI 문체에 관한 [Shan 등의 문체 분석 연구](https://arxiv.org/abs/2608.27855)도 생성기와 글의 분야에 따라 특징이 달라지고 AI 편집과 AI 작성의 양상이 다르다고 보고한다. 이 연구로 한국어의 특정 종결어미를 판별 기준으로 정할 수는 없다. 이번 자가 평가는 AI 작성 여부의 추정 대신 실제 시안에서 독자가 불편해한 표현과 읽기 부담을 교정하는 데 사용한다.

[NN/g의 시각적 위계](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)는 중요도와 시선의 순서를 함께 다루며, [제목 중심 훑어읽기 연구](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)는 내용에 맞는 제목과 본문의 시각적 연결을 강조한다. FR5에서는 제목만 읽어도 각 부분의 질문이 구별되는지, 첫 시선이 의도한 대상에 머무는지 확인한다. 특정 색·글꼴·시간 제한을 보편적 합격 공식으로 삼지는 않는다.

색상 변경이나 모션 추가만으로 이 결함들을 해결했다고 판정하지 않는다.

## 다음 시안의 읽기 경로

시스템 이해는 포트폴리오 사례 조사와 별도로 계속한다. 실제 코드에서 Curator의 영상 변환 후보 준비와 기존 수집 기록의 학습 요청 발행을 구분했고, coverage 기반 추천과 실제 rollout 분석 소비도 같은 연결로 가정하지 않았다. 외부의 [LeRobotDataset 설명](https://huggingface.co/docs/lerobot/en/lerobot-dataset-v3)은 episode와 저장 파일의 관계를 이해하는 데, [C4의 확대 수준](https://c4model.com/diagrams)은 전체와 세부 설명을 구분하는 데 참고했다. 웹 문서의 현재 API나 보편적 설명을 FR5의 실제 동작으로 대신하지 않는다. 구체적인 추적 경로와 발견한 연결의 빈틈은 내부 메모에서 유지하고 main에 전달한다.

전체 소개의 목적은 **FR5가 다루는 작업과 시스템의 큰 관계를 이해하는 것**이다. 여기서 모든 기능의 구현 세부나 실험 수치를 읽게 하지 않는다. 아키텍처 설명은 **역할을 왜 나눴고 실제로 무엇을 주고받는지**를 다룬다. 개별 기능의 설명은 **그 부분이 해결한 문제와 선택한 구현의 이유**를, 연구 사례는 **어떤 질문을 어떤 조건에서 검증했고 무엇을 알게 됐는지**를 맡는다. 운용 사례도 실제 문제·교정·확인 범위가 있으면 독립적인 가치로 제시한다.

페이지를 나누는 기준은 lane 이름이나 파일 개수가 아니라 읽는 목적이다. 한 lane의 기능 설명과 연구가 서로 다른 페이지에 놓일 수 있고, 여러 lane이 공동으로 만든 결과는 하나의 사례에서 연결할 수 있다. 세부 페이지에는 현재 위치와 관련 입력·다음 소비자로 가는 경로가 있어야 한다. 숨겨 둔 긴 내용을 전부 펼쳐야 전체를 이해하는 구성도 피한다.

현재의 작은 결과는 전체 개요에서 시스템 구성과 세부 주제 목록으로 이동하고 돌아올 수 있는 틀이다. 기능·연구·운용·검증의 세부 내용은 후보만 적는다. 최근 성과를 대표 사례로 고르거나, 개별 사례의 상세 화면을 먼저 제작하지 않는다. 원래 owner의 추적 경로는 내부에서 유지하고, 나중에 내용을 채울 때 최신 근거를 확인한다.

## 렌더 후 스스로 답할 질문

- 각 페이지의 제목·대표 매체·첫 설명이 같은 목적을 향하는가? 제목만 읽어도 전체와 부분의 관계가 남는가?
- 독자가 세부에 직접 들어와도 무엇의 일부인지 알 수 있는가? 관련 기능이나 전체로 돌아오는 링크가 실제로 작동하는가?
- 조작 전후에 확인할 내용이 명확한가? 데이터 선택과 문장·표·영상이 함께 바뀌는가?
- 데스크톱에서 읽을 때 시선이 흩어지거나 설명이 끊기지 않는가? 키보드로 이동할 수 있고, 움직임을 줄여도 내용이 남는가?
- 수치와 한계가 같은 원본에 연결되는가? 유리한 평균 옆에서 반례·비교 조건을 확인할 수 있는가?
- 초기 학습 진단을 모델·데이터의 근본 한계로 해석하거나, 설계된 연결을 실제 자율 운용으로 표현하지 않았는가?
- 새 성과나 반증은 기존 owner 출력에서 같은 사례로 반영되는가? 문서·그림·발표용 결과 장부를 따로 만들지 않았는가?

디자인 수용 여부는 사용자의 실제 반응으로 확인한다. 이 기준을 작성하거나 자체 검토를 통과했다는 사실만으로 취향 검토와 전체 포트폴리오의 완료를 선언하지 않는다.


## 세부 구성과 정리의 시점

사용자의 추가 방향: 각 부분을 같은 형식으로 맞출 필요는 없다. 독자가 핵심을 가장 쉽게 파악하고 기억할 구성을 고른다. 연결 관계를 이해해야 하는 내용과 시간에 따른 변화를 읽어야 하는 내용은 서로 다른 구성이 필요할 수 있다. 한 장면으로 충분하면 길게 늘이지 않고, 맥락이 필요한 내용에는 충분한 공간을 준다. 기능·연구·운용이라는 분류에 특정 매체를 미리 배정하지 않는다.

공통으로 유지할 것은 읽는 위치, 용어, 근거와 한계에 접근하는 방식이다. 같은 카드 수, 문단 수, 분량이나 고정된 문제→해결→성과 순서를 강제하지 않는다. 도해·영상·비교·상호작용은 해당 내용을 더 잘 이해하게 할 때 선택하고 실제 렌더와 사용으로 판단한다. 화면의 강조가 아직 검증하지 않은 중요도를 암시하지 않는지도 확인한다.

| 지금 정리할 내용 | 판단을 더 기다릴 내용과 다시 볼 시점 |
| --- | --- |
| 전체와 세부의 역할, 중복 설명, 같은 대상을 부르는 용어, 왕복 탐색 경로 | 대표 사례와 비중: 후보들의 실제 근거와 한계를 함께 검토할 수 있을 때 |
| source와 실제 산출물의 추적 경로, 확인한 연결과 빈틈 | 주장·수치·결론: 해당 내용을 채우는 시점의 canonical output을 읽고 나서 |
| 후보 목록에서 이미 구별되는 질문과 설명 범위 | 페이지를 합치거나 나눌 기준, 최종 순서: 실제 내용으로 읽어 보며 목적의 중복과 단절이 드러날 때 |
| 반복되는 편집 안내를 줄이고 각 단락의 목적을 드러내는 문장 | 도해·영상·상호작용과 분량: 보여줄 대상이 정해지고 작은 표현물을 직접 사용해 본 뒤 |

기다릴 내용도 영구 보류하지 않는다. 원본 변화나 사용 중 발견한 혼란이 판단에 필요한 정보를 주면 그 부분부터 다시 정리한다. 지금의 후보 목록은 재료 목록이며 최종 페이지 구성의 견본이 아니다. 새 자료를 받을 때마다 전체를 다시 만들지 않고 관련 설명과 연결을 고친다. 데스크톱 구성을 대상으로 이미지·영상 등 포함 자산까지 전체 50MB 이하를 유지한다.
