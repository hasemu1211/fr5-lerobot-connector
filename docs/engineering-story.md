# 주요 설계 판단

실물 시연을 반복해서 만들려면 로봇 동작뿐 아니라, 무엇을 바꿔 수집하고 어디까지 학습 데이터로 남길지도 정해야 한다. 이 프로젝트에서는 수집 조건과 기록 범위를 먼저 정의하고, 선별·학습 이후에도 원래 조건으로 돌아갈 수 있도록 연결했다.

| 설계 선택 | 이유 | 구현에서 지킨 기준 |
| --- | --- | --- |
| 작업영역 안에서 위치·각도를 바꿔 시연 생성 | 같은 동작만 반복하면 배울 조건이 좁아진다 | 물체 외곽을 고려해 배치하고, 등록한 좌표계로 목표 자세를 계산 |
| 작업 동작과 다음 시연 준비를 분리 | 재배치·복귀까지 기록하면 학습할 행동에 준비 동작이 섞인다 | 작업 정의에 따라 기록 시작·종료 지점을 결정 |
| 실행 완료와 저장 완료를 분리 | 저장 응답이 늦어도 로봇 동작을 다시 실행하면 안 된다 | 진행 중인 저장을 기다리되 완료한 동작은 반복하지 않음 |
| 재접속한 화면에서 서버의 작업 상태를 복원 | 화면 연결이 끊겼다고 로봇의 작업 상태까지 사라지는 것은 아니다 | 이전 명령의 재전달을 새 실행으로 처리하지 않음 |
| 저장 품질·작업 성공·학습 사용을 별도로 판정 | 파일이 정상이라고 올바른 시연이거나 유용한 학습 데이터인 것은 아니다 | 자동 검사와 사람의 검토, 학습 승인을 분리 |
| 원본 조건과 평가 대상을 보존 | 데이터와 정책을 바꾸면서 비교 기준까지 달라지면 개선을 해석하기 어렵다 | 같은 평가 입력으로 비교하고, 실행 결과를 원래 수집 조건에 대응 |

수집 조건과 좌표계는 [시연 생성 설계](data-factory.md), 작업별 기록 구간은 [기록 범위](portfolio/collection.html#recording-scope)에서 설명한다.

## 실패 단위에 맞춘 모듈 책임

로봇 동작이 끝나도 영상 저장은 계속될 수 있다. 저장 응답이 늦다는 이유로 같은 동작을 다시 실행하면 안 된다. OneJob은 시연의 동작·중단을, Recorder는 기록·저장을 각각 관리하고 완료 상태를 대조한다. [아키텍처](architecture.md)에서 전체 흐름과 모듈 책임을 확인할 수 있다.

## 재접속해도 중복 실행하지 않는 화면

수집 시작을 눌렀는데 응답 전에 화면 연결이 끊길 수 있다. 재접속한 화면은 서버에서 진행 중인 작업을 읽어 온다. 서버는 명령의 상태 버전·식별값과 중복 여부를 확인하므로, 재접속을 새 수집으로 처리하지 않는다. 구현 선택은 [운영 화면의 아키텍처](../operator-ui/architecture.md), 회귀 검증은 [브라우저 테스트](../operator-ui/tests/)에 연결된다.

## 데이터 품질과 작업 성공의 분리

시각 정보, 누락된 표본, 영상 디코딩과 데이터 구조는 자동으로 검사할 수 있다. 그러나 “올바른 물체를 집었는가”는 저장 검사만으로 알 수 없다. 자동 검사의 통과, 사람의 시연 검토, 학습 사용 승인을 별도 상태로 관리하는 이유다. 판정 기준은 [데이터셋 품질](dataset-quality.md), 회귀 검사는 [기록 품질 테스트](../tests/test_recorder_quality.py)와 [판정 상태 테스트](../tests/test_handling_ssot.py)에서 확인할 수 있다.

## 연속 수집의 좌표 정밀도

연속 pick-place 수집에서 로봇이 놓은 위치와 다음 episode의 시작 위치가 같은데도 서버가 다음 시작을 거절한 사례가 있었다. 원인은 같은 yaw의 좌표를 회전했다가 역회전하며 생긴 부동소수점 오차였다. 위치 허용오차를 넓히는 대신, 변환이 필요 없는 경우 원래 좌표를 그대로 전달해 scene slot과 다음 source의 정확한 결속을 유지한다.

실제 실패 좌표는 [좌표 회귀 테스트](../tests/data_factory/test_object_reposition.py)에, source·slot·run 결속과 잘못된 다음 위치의 거절은 [runner 계약 테스트](../tests/data_factory/test_run_job.py)에 남긴다. 아래 명령은 로봇 없이 이 오류와 fail-closed 경계를 검증한다. 통과 자체가 실물 연속 수집 성공률을 증명하지는 않는다.

```sh
direnv exec . python3 -m unittest \
  tests.data_factory.test_object_reposition \
  tests.data_factory.test_run_job.RunJobTest.test_chain_landed_source_is_bound_by_the_root_resolver_before_live_side_effects
```

## 원본에서 결과까지의 추적

각 시연에는 어떤 계획과 조건으로 수집했는지 남기고, 학습·평가 결과에는 사용한 데이터와 정책을 연결한다. 로봇이 물체를 옮긴 뒤에도 실행 당시 조건을 보존하므로, 현재 장면을 과거 실행의 입력으로 잘못 해석하지 않는다. 이 연결은 [다음 수집 추천](architecture.md#task--evidence-contracts)과 [평가 대상 보존](training-and-evaluation.md#split--normalization)에 사용된다.

저장·승인 경로는 [데이터팩토리 계약](data-factory.md), 품질 판정은 [데이터셋 품질](dataset-quality.md), 학습 입력과 평가 조건은 [학습과 평가](training-and-evaluation.md)에서 설명한다. 원본 데이터와 실행 보고서를 유지하고 문서에서는 해당 근거를 연결한다.
